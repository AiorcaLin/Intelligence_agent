## 4. 修复方向建议

### 方案 A：修前端适配后端（推荐）

> 后端 API 设计合理，前端尚未联调，改前端成本较低

- **优点**：后端不动，减少回归风险
- **缺点**：前端改动量大（约 8 个文件）
- **工作量估计**：~4 小时

### 方案 B：修后端适配前端

> 把后端 API 改成前端期望的形状

- **优点**：前端代码不改
- **缺点**：后端改动面广，需要同时改路由、Schema、服务层
- **工作量估计**：~6 小时

### 方案 C：双向对齐（推荐大项目）

> 先定义 API 契约文档（OpenAPI spec），再双向修改

- **优点**：最规范，长期可维护
- **缺点**：耗时最长
- **工作量估计**：~8 小时
