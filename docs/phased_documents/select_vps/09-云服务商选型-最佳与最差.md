# 云服务商选型 — 最佳 3 / 最差 3（第 9 轮 · 阶段性总结）

**日期**：2026-04-12  
**前提**：暂不修改业务代码；目标为 **云上 Linux**，规格约 **2–4 vCPU、8 GB 内存、60–80 GB SSD**（与先前 `02` 篇一致）；单人使用；需访问 **境外 HTTPS API**（如 OpenRouter、默认嵌入所用 OpenAI 等）与 **国内可达的 DeepSeek**；人在国内（成都），倾向 **人民币支付与中文控制台** 者优先，但不强制。

**说明**：云厂商价格、活动与线路**随时变化**，下表为 **架构与风险维度** 的选型判断，**不是**当期最低价目表；下单前请以官网为准。

---

## 一、对「本项目」而言较好的 3 类选择（类型级推荐）

下列按 **与本项目匹配度** 排序：Docker 全栈、出站 HTTPS、单人运维成本、支付与合规摩擦。

### 1）国内大厂 · 轻量应用服务器 · **中国香港 / 新加坡**（阿里云 / 腾讯云等）

| 维度 | 说明 |
|:---|:---|
| **为何适合** | 支持 **人民币/国内主体** 购买；**海外地域** 一般 **免 ICP 备案**，且相对 **大陆地域** 更易获得稳定的 **国际互联网访问**，利于 OpenRouter、OpenAI 嵌入等出站（仍建议购机后 `curl` 实测）。**参考**：阿里云轻量实例规格与地域说明见 [实例规格族概述](https://help.aliyun.com/zh/simple-application-server/product-overview/instance-families/)。 |
| **与本项目** | 控制台一键装 Docker 类镜像较成熟；2–4 vCPU / 8 GB / 60 GB+ 档位常见；适合「一人项目、要省心」。 |
| **注意** | 看清 **流量包/峰值带宽**；续费价可能高于首购；**地域创建后通常不可迁**。 |

### 2）**Hetzner** Cloud（优先 **新加坡**；备选欧洲）

| 维度 | 说明 |
|:---|:---|
| **为何适合** | 在开发者社区中长期以 **性价比与透明计费** 著称，适合跑 Docker 与常驻服务。**参考**：[Hetzner Cloud 产品页](https://www.hetzner.com/cloud)（定价与区域以官网为准）。 |
| **与本项目** | 国际出站质量通常较好；新加坡对东亚延迟相对友好。 |
| **注意** | 需 **国际支付/账单习惯**；对中国用户可能存在 **注册/风控** 摩擦；**2026 年起官方已公告调价**，需以当前价为准。**参考**：[Hetzner 调价说明（新闻稿）](https://www.hetzner.com/pressroom/statement-price-adjustment/)。 |

### 3）**Vultr** / **DigitalOcean**（优先 **东京 / 新加坡**）

| 维度 | 说明 |
|:---|:---|
| **为何适合** | 面向开发者的 **按小时/按月** 云主机，**文档与社区教程多**，Docker 部署资料全；多地域可选。 |
| **与本项目** | 易与 GitHub Actions、Terraform 等联动；适合你能接受 **美元计价 + 双币信用卡/PayPal** 的场景。 |
| **注意** | 从中国大陆 **SSH 管理** 的延迟与抖动因运营商而异；**与「API 出站是否稳」不是一回事**，仍需在实例上测 API。 |

## 二、对「本项目」而言较差的 3 类选择（类型级避雷）

### 1）**Oracle Cloud Infrastructure — Always Free**（作为「唯一、长期、生产唯一载体」）

| 维度 | 说明 |
|:---|:---|
| **为何不匹配** | 免费资源 **无商业 SLA**、热门区域常出现 **容量不足无法创建**；账户与合规风险需自担。**参考**：[Oracle Cloud — Always Free Resources](https://docs.oracle.com/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)。**解释**：文档明确_always free_ 资源边界；适合学习/试验，**不适合**作为「我只这一台机、必须一直在线」的唯一依赖。 |

### 2）**极低价年付、口碑不明的「超售」VPS 小厂**

| 维度 | 说明 |
|:---|:---|
| **为何不匹配** | 磁盘/带宽/CPU **严重超售**时，Docker 多容器 + 数据库会出现 **随机卡顿、IO 延迟飙升**，排错成本远高于省下的月费。 |
| **与本项目** | Postgres、Chroma、Celery 对 **稳定 IO 与内存** 敏感；此类主机常见问题与「代码 bug」难以区分。 |

### 3）**仅中国大陆地域、且未配套国际出口优化，却强依赖境外 API**

| 维度 | 说明 |
|:---|:---|
| **为何不匹配** | 若你的链路强依赖 **OpenRouter / OpenAI 嵌入** 等境外端点，而实例只有 **普通大陆公网出站**，可能出现 **间歇超时**；这不是 CPU 不够，而是 **网络路径** 问题。 |
| **与本项目** | 与 `02` / `05` 篇结论一致：要么选 **海外地域/精品线路**，要么把嵌入改为 **国内兼容接口**（代码层，后议）。 |

---

## 三、与你给定规格的对应关系

- **2–4 vCPU / 8 GB / 60–80 GB SSD**：上述 **「最佳」三类** 均有相近档位；优先保证 **内存 ≥ 8 GB** 再缩 CPU，通常更符合 Docker 全栈。  
- **「暂不修改代码」**：若嵌入仍走 OpenAI，**网络类「最差」第 3 条** 会更痛；跑通后再按 `05` 篇换国内嵌入最稳。

## 四、我仍建议你补充的信息（非必须，但可缩小到具体 SKU）

1. **支付方式**：是否 **必须人民币/支付宝/微信**？—— 决定能否选 Hetzner/Vultr 一类。  
2. **管理路径**：你是否需要 **从成都低延迟 SSH**，还是只关心 **服务器访问境外 API**？—— 前者影响地域与运营商，后者影响 **HK/SG/东京** 选择与实测。
