## 逐项分析

### 1. CPU — 2 vCPU ✅

- FastAPI + Uvicorn 是**异步框架**，CPU 消耗极低，LLM 调用只是 HTTPS 出站，不本地推理
- Celery Worker 单用户情况下 CPU 闲置为主
- Next.js 运行时（`next start`）CPU 低
- **风险**：若在服务器上执行 `next build`，会短时爆 CPU；**建议在本机或 CI 构建后上传产物**

### 2. 内存 — 8 GB ✅（含估算）

| 组件 | 估算常驻内存 |
|:---|:---:|
| postgres:16-alpine（Docker） | ~200–400 MB |
| redis:7-alpine（Docker） | ~30–80 MB |
| chromadb/chroma（Docker） | ~200–500 MB |
| Docker 守护进程及 overlay | ~200–300 MB |
| Uvicorn/FastAPI 进程 | ~200–400 MB |
| Celery Worker（含 Beat） | ~200–400 MB |
| Next.js `next start` | ~200–400 MB |
| 操作系统 + 其它 | ~400–600 MB |
| **合计（估算）** | **~1.6–3.1 GB** |

8 GB 下**约有 5 GB 余量**，单人测试时充裕。  
**关键注意**：如果在服务器直接 `next build`，内存峰值可至 3–4 GB，依然在 8 GB 内，但留的余量变少——建议**不在服务器现场构建**。  
**参考**：[Next.js — Memory Usage](https://nextjs.org/docs/app/guides/memory-usage)

### 3. 磁盘 — 80 GB SSD ✅

| 用途 | 估算占用 |
|:---|:---:|
| 操作系统 | ~5 GB |
| Docker 镜像（三个容器）| ~2–4 GB |
| Python venv + 依赖 | ~0.5–1 GB |
| Node modules（Next） | ~0.5–1 GB |
| 数据库 + Chroma 数据 | 初期 <1 GB，随使用增长 |
| 日志 | 需定期清理 |
| **合计** | **~10–15 GB 起步** |

80 GB 对测试阶段够用；**需监控磁盘**，防止日志和数据库无限增长。

### 4. 带宽（200 Mbps，无限流量） ✅

完全不是瓶颈。本项目所有 LLM 调用均为 API 文本交换，带宽消耗极低。

## 网络出站评估（香港机房 → 各 API）

### DeepSeek — ✅ 通常正常

官方 `base_url`：`https://api.deepseek.com`  
**参考**：[DeepSeek API 文档](https://api-docs.deepseek.com/)  
香港到 DeepSeek 一般可达；**上机后用 `curl` 探活确认**：
```bash
curl -sS -o /dev/null -w "%{http_code}" https://api.deepseek.com
```

### Claude（直连 Anthropic） — ⚠️ 需上机验证

当前代码（`llm_router.py`）中 `anthropic/...` 任务通过 `CLAUDE_API_KEY` 直连 Anthropic：
```python
elif model.startswith("anthropic/"):
    api_key = settings.CLAUDE_API_KEY
```
Anthropic 对香港无公开封锁文档，但**需在香港实例上实测能否连通**。若失败，可改为通过 **OpenRouter** 代理 Claude（属代码改动，后续再议）。

### OpenAI Embeddings — ❌ 关键阻碍

当前 `embedding.py` 使用 **OpenAI 官方客户端**与 `text-embedding-3-small`：
```python
_openai_client = openai.AsyncOpenAI(api_key=settings.OPENAI_API_KEY)
response = await client.embeddings.create(model=settings.EMBEDDING_MODEL, ...)
```
**OpenAI 官方明确**：中国香港**不在** API 支持地区列表。使用可能导致账号被封。  
**参考**：[OpenAI API — Supported Countries and Territories](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories)

**这是目前全流程最大的阻碍**，不是网络问题，是政策问题。

## 嵌入替换方向（你说「遇到再说」时的参考）

若你后续愿意改这一处，改动量极小：只需在 `config.py` 加一个 `EMBEDDING_BASE_URL`，在 `embedding.py` 里把：
```python
openai.AsyncOpenAI(api_key=settings.OPENAI_API_KEY)
```
改为：
```python
openai.AsyncOpenAI(api_key=settings.OPENAI_API_KEY, base_url=settings.EMBEDDING_BASE_URL)
```
然后在 `.env` 里把 `EMBEDDING_BASE_URL` 指向 **DashScope/SiliconFlow** 等兼容 `/v1/embeddings` 的端点即可，模型名同步改成对应的嵌入模型。**维度需与 Chroma 中已有数据一致，或清空重建向量库。**
