## 2. 参考资料（用于后续定量评估的「科学依据」）

1. **PostgreSQL 内存与资源参数**  
   - 官方文档 [Runtime Configuration: Resource Consumption](https://www.postgresql.org/docs/current/runtime-config-resource.html) 说明 `shared_buffers`、`work_mem`、`maintenance_work_mem` 等与内存、并发查询的关系；**不是**单一「最低内存数字」，而是随负载与并发变化。  
   - **解释**：评估 DB 容器或虚拟机时，需要结合连接数、查询复杂度与数据量，用上述参数族估算 RAM 上限与是否需要调优。

2. **Next.js 构建与运行时内存**  
   - 官方指南 [Memory Usage](https://nextjs.org/docs/app/guides/memory-usage) 讨论构建/运行时的内存行为与排查思路。  
   - **解释**：前端资源评估应区分 **`next build`（峰值常显著高于 dev server）** 与 **`next start`/`next dev`（持续占用）**；CI 或低配机器上构建往往是瓶颈。

3. **Docker 中的 Node/OOM**（实践层面）  
   - 容器 `memory limit` 与 Node 默认堆上限不匹配时易发生 OOM；常配合 `NODE_OPTIONS=--max-old-space-size=...` 对齐（见 Next.js Memory Usage 与常见运维实践）。  
   - **解释**：若你用 Docker 跑前端构建，**限额 + Node 堆** 要一起算，不能只看镜像大小。
