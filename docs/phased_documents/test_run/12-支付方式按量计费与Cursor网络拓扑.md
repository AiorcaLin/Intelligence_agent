# 支付方式、按量计费与 Cursor / 网络拓扑（第 12 轮 · 阶段性总结）

**日期**：2026-04-12  
**输入**：可使用 **USDC/USDT** 等加密货币支付；倾向 **按量/按小时** 计费（当前测试，成功后扩容）；人在 **成都**，用 **Cursor** 调试；当前 Cursor 相关流量经 **日本 VPS 代理**；关心 **延迟不影响调试**；意识到未来可能存在 **「服务器 → 本机 → 日本代理」** 的绕路问题。

---

## 1. Cursor 究竟「在成都」还是「在远端」？

**简短结论**：**Cursor 编辑器应用运行在你成都的电脑上**；是否「远端」取决于你打开的是 **本地文件夹** 还是 **Remote SSH 远程工程**。

| 模式 | 哪里跑 UI | 哪里跑代码/终端/构建 | 典型延迟感受 |
|:---|:---|:---|:---|
| **本地开发** | 成都本机 | 本机 | 仅受本机性能影响；访问远端 API 时走本机网络。 |
| **Remote SSH（与 VS Code 远程机制同类）** | 成都本机 | **SSH 目标机**（如你的业务 VPS） | 编辑器与 AI 对话仍在本地；**文件保存、终端、语言服务** 走 SSH；延迟主要来自 **你 ↔ VPS 的 RTT**。**解释**：远程开发时，远端会跑 VS Code / Cursor 兼容的服务端组件，负载在远端完成。**参考**：[Cursor Remote Development via SSH and Tunnel](https://docs.rc.fas.harvard.edu/kb/cursor-remote-development-via-ssh-and-tunnel/)（原理说明；若链接变更以 Cursor 官方论坛/文档为准）。 |

**因此**：不是「把 Cursor 安装到东京」，而是 **「代理只影响 Cursor 访问其 AI 服务/更新的路径」**；你的 **项目文件** 可以在成都磁盘，也可以在远端 VPS。

## 2. 按量计费 + 加密货币：与「测试期」的匹配

- **按小时/按秒扣费** 的公有云（如 Vultr、DigitalOcean、Linode/Akamai、部分区域 AWS/GCP 小实例）适合 **短期试跑**，可随时删机止损。  
- **直接 USDC/USDT 入账** 并非所有一线厂商原生支持；常见路径包括：  
  - 厂商集成 **BitPay** 等（以官网当期支付方式为准；例如社区常提及 Vultr 与 BitPay 的组合，**需你自行在官网核对**）。**参考**：[BitPay 商户目录中的 Vultr 条目](https://www.bitpay.com/directory/vultr)（第三方目录，以 Vultr 结账页为准）。  
  - **加密货币转售/聚合平台**（如 BitLaunch、bithost 等）代开 DO/Vultr/Linode 资源——**务必自行审查信誉与条款**，避免资金风险。  

**解释**：按量计费解决「测试期成本」；加密货币解决「无国内信用卡」；二者可叠加，但 **以目标云厂商官网与合规要求为准**。

## 3. 延迟：怎样才算「不影响调试」？

对你当前项目，调试分三类流量，**不要混在一起谈「一个延迟」**：

| 流量类型 | 关注点 | 建议 |
|:---|:---|:---|
| **A. Cursor AI（补全/对话）** | 经日本代理到 Cursor 服务 | 只要 **SSH/编辑不卡** 即可；AI 回答慢几秒通常仍可接受。 |
| **B. 你 ↔ 业务 VPS（SSH / Remote SSH）** | **成都到机房 RTT** | 选 **香港 / 新加坡 / 东京** 等，一般 **几十毫秒级**，对编辑与终端通常足够。 |
| **C. 业务 VPS ↔ DeepSeek/OpenRouter 等 API** | **出站国际 HTTPS** | 应在 **VPS 上** 直连或短路径完成；**不要**强行经你家用电脑转发（见下节）。 |

**解释**：你担心的「服务器 → 电脑 → 日本」若用于 **API 调用**，会把 **C 类流量** 拉长成灾难级延迟；正确做法是 **API 只在服务器上出网**，你的电脑只跑 **A+B**。

---

## 4. 你提到的绕路问题：如何避免？

**不推荐路径**：应用跑在 VPS A → 通过隧道回到成都 → 再经日本代理去访问公网 API。  
**推荐路径**：

1. **应用与 Celery 只在业务 VPS 上运行**，对外 API **由 VPS 直接出站**（与 `02`/`05`/`09` 篇一致）。  
2. **Cursor 仅用于编辑/部署**：  
   - 代码在本地：用 **Git push / CI / rsync** 部署到 VPS；  
   - 或 **Remote SSH 直接连业务 VPS**，避免大文件经代理来回传。  
3. **代理用途收窄**：日本节点主要用于 **Cursor/浏览器访问境外**；**SSH 到 VPS** 可尽量 **直连或走更短路径**（在 `.ssh/config` 里为 `Host` 单独指定 `ProxyCommand` 或 **不走代理**，按你运营商实测为准）。  

若未来你在「新服务器」上自建 **VPN/代理节点**：更适合解决 **你从成都访问 GitHub/HuggingFace** 等，而不是让 **后端 API 流量绕回家**。
